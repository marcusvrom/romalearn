# Preparação dos cursos de tecnologia para lançamento

## Objetivo

Aproximar a trilha técnica de uma versão comercialmente publicável sem esconder o que ainda precisa de validação com alunos reais.

## Estrutura entregue

Cada curso possui:

- proposta e resultado profissional claros;
- primeira aula como amostra;
- capítulos com aprendizagem ativa;
- práticas intermediárias;
- projeto final;
- critérios públicos de aprovação;
- questionário de conclusão;
- continuidade recomendada na trilha;
- produto e oferta de homologação.

## Padrão didático das aulas

As aulas conceituais seguem o mesmo roteiro:

1. objetivo da aula;
2. ativação de conhecimento prévio;
3. explicação em passos;
4. exemplo guiado;
5. alteração do exemplo;
6. teste comum, limite e inválido;
7. erros comuns;
8. checklist de conclusão;
9. conexão com o projeto final.

O aluno não deve avançar somente por leitura. Cada capítulo pede reprodução, alteração, previsão e registro da descoberta.

## Avaliação

### Práticas intermediárias

Validam aplicação pontual e exigem relato do processo.

### Projeto final

Exige aprovação por rubrica. Os critérios ficam visíveis antes da entrega e somam 100 pontos. A nota mínima sugerida é 70.

### Questionário de conclusão

Cada curso possui avaliação objetiva com:

- tentativas ilimitadas;
- opções embaralhadas;
- feedback explicativo;
- aprovação mínima de 70%;
- foco em compreensão, não memorização de sintaxe.

## Trilha de Desenvolvimento de Software

Ordem principal:

1. Lógica de Programação e Algoritmos;
2. Git e GitHub na Prática;
3. HTML e CSS do Zero;
4. JavaScript — Fundamentos;
5. especialização inicial em Python ou Java.

A trilha possui produto próprio de homologação. O preço é sandbox e não representa decisão comercial final.

## Checklist antes da venda oficial

### Conteúdo

- [ ] Revisar tecnicamente todos os exemplos.
- [ ] Adicionar exemplos completos específicos por capítulo.
- [ ] Disponibilizar repositórios iniciais e soluções comentadas.
- [ ] Garantir que comandos funcionem em Windows, macOS e Linux quando aplicável.
- [ ] Revisar termos em inglês e pronúncia do modo áudio.
- [ ] Verificar tempo real de cada aula com usuários iniciantes.

### Projetos

- [ ] Criar um repositório modelo para cada curso.
- [ ] Criar dados fictícios de exemplo.
- [ ] Publicar uma entrega de referência sem torná-la copiável diretamente.
- [ ] Validar a rubrica com pelo menos três entregas de teste.
- [ ] Confirmar limites e formatos de anexos.

### Experiência

- [ ] Exibir claramente o projeto final na página comercial.
- [ ] Mostrar pré-requisitos e próxima etapa.
- [ ] Indicar ferramentas que precisam ser instaladas.
- [ ] Oferecer ajuda específica por linguagem no assistente de suporte.
- [ ] Sincronizar progresso, velocidade do áudio e última aula.

### Qualidade

- [ ] Executar seed em banco vazio.
- [ ] Executar seed duas vezes e confirmar idempotência.
- [ ] Executar lint, testes e builds.
- [ ] Concluir um curso inteiro com usuário de teste.
- [ ] Emitir e validar certificado.
- [ ] Testar oferta gratuita e checkout sandbox.

## Métricas para a Beta

Por curso:

- visualizações da página;
- início da amostra;
- conclusão da amostra;
- matrícula ou compra;
- ativação em até 48 horas;
- conclusão por capítulo;
- abandono por aula;
- dúvidas e chamados;
- uso do áudio;
- entrega e aprovação do projeto;
- nota e tentativas no questionário;
- conclusão e emissão de certificado.

## Critério de pronto

Um curso pode ser vendido quando:

1. exemplos e comandos foram executados por outra pessoa;
2. pelo menos cinco alunos iniciantes concluíram a jornada principal;
3. o projeto final foi entregue e corrigido sem intervenção técnica no banco;
4. dúvidas recorrentes estão cobertas pelo suporte inteligente;
5. pagamento, acesso, progresso e certificado funcionam ponta a ponta;
6. não existem afirmações de resultado profissional que a plataforma não possa sustentar.
